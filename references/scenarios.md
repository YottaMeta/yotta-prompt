# 场景案例库（元引 yotta-prompt）

> 每个场景给完整链路：**模糊输入 → 候选方向 → 深挖 → 串联技能 → 可直接运行的提示词**。
> 智能体执行时按此节奏走，别跳步、别替用户下结论。

> 每个「可跑提示词」均为**自包含版本**：目标技能未安装也能直接运行；装了对应技能，
> 提示词括号内的「若已安装 …」会调用其方法论自动增强。
> 场景不限于技术 / 安全——写周报、做表格、定计划、写演讲稿、翻译、会议纪要、审合同、
> 头脑风暴、面试准备等任何行业 / 场景都可按同一五步流程引导。

---

## 1. 想写一封邮件（email → writing）

- **模糊输入**：「帮我写个邮件」
- **候选**：① 写作与语言（写邮件 / 润色 / 降噪）② 通用与入门（先理清再说）
- **深挖**：给谁写？什么事？语气正式还是亲切？多长？
- **串联**：元真 yotta-humanize
- **可跑提示词**：
  > 请以中文帮我写一封邮件：收件人 <对象>，主题 <主题>，正文要点 <要点>，语气 <正式/亲切>，长度 <限制>。写完后自查 AI 味（少用「首先 / 其次 / 此外」等套话、避免过度正式）并按需改写。（若已安装元真 yotta-humanize，请先跑检测评分再改写）

## 2. 想学一个概念（learn-concept → learning）

- **模糊输入**：「机器学习是啥」
- **候选**：① 学习与教学（概念 / 入门）② 通用与入门
- **深挖**：想学到什么程度？有基础吗？要例子还是练习？
- **串联**：元习 yotta-learn
- **可跑提示词**：
  > 请帮我学习 <主题>：先讲清核心概念与原理，给 2-3 个例子，再出一个练习并给反馈；把新知识点记入长期记忆。（若已安装元习 yotta-learn，请按它的学习循环执行）

## 3. 怕忘事（remember → memory）

- **模糊输入**：「帮我记住这个」
- **候选**：① 记忆与跨会话（记一笔 / 别忘）② 通用与入门
- **深挖**：记什么？是公共共享、个人偏好还是私密信息？下次会话还要用吗？
- **串联**：元忆 yotta-memory（必要时元序 yotta-workflow 管交接）
- **可跑提示词**：
  > 请把 <要记住的信息> 记入我的长期记忆：标注类型（公共共享 / 个人偏好 / 私密），说明后续如何回忆，并在本会话收工时归档。（若已安装元忆 yotta-memory，请用它的 CLI 写入并声明身份）

## 4. 看日志排障（troubleshoot → logs）

- **模糊输入**：「日志里好像报错了」
- **候选**：① 日志与运维（检索 / 统计 / 排障）② 安全与合规（日志审计）
- **深挖**：哪里的日志？找什么关键字？哪个时间段？要匹配行还是统计报告？
- **串联**：元史 yotta-logs（监控场景用元察 yotta-logwatch）
- **可跑提示词**：
  > 请检索 <日志位置>：关键词 <关键字>，时间范围 <范围>，输出 <匹配行 / 统计 / 报告>。（若已安装元史 yotta-logs，请用它的检索 CLI）

## 5. 代码有 bug（code-bug → dev）

- **模糊输入**：「这段代码为什么报错」
- **候选**：① 开发与代码（调试 / 重构 / 质量评审）② 严谨与质量（自检）
- **深挖**：什么语言？完整报错信息？期望行为是什么？
- **串联**：元质 yotta-code-quality（必要时刻度：元盾 yotta-guardian 拦危险调用）
- **可跑提示词**：
  > 请帮我排查这段 <语言> 代码的报错：报错信息 <报错>，期望行为 <行为>。先定位根因再给修复，写完自查边界情况，并按代码质量评审标准过一遍。（若已安装元质 yotta-code-quality，请按它的十二类风险标准评审）

## 6. 查密钥泄露（secret-scan → security）

- **模糊输入**：「看看项目里有没有密钥」
- **候选**：① 安全与合规（密钥扫描 / 审计）② 开发与代码
- **深挖**：扫哪个目录 / 仓库？含 git 历史吗？发现后要做什么（打码 / 报告）？
- **串联**：元钥 yotta-secret（深度审计：元安 yotta-security-audit）
- **可跑提示词**：
  > 请对 <路径 / 仓库> 做一次密钥与凭据泄露自查（含 git 历史）：先明确授权范围，再扫描，输出结构化报告；发现疑似密钥先打码，不打印明文。（若已安装元钥 yotta-secret，请用它的引擎扫描）

## 7. 去 AI 味（de-ai → writing）

- **模糊输入**：「写的东西一股 AI 味」
- **候选**：① 写作与语言（去 AI 味 / 口语化 / 降噪）② 通用与入门
- **深挖**：哪段文字？希望更像谁的语气（口语 / 朋友 / 同事）？
- **串联**：元真 yotta-humanize
- **可跑提示词**：
  > 请检测并改写这段文字以去除 AI 味：目标语气 <口语 / 自然 / 正式>；输出「前后评分 + 修复清单 + 改写后文本」。（若已安装元真 yotta-humanize，请用它的检测与改写引擎）

## 8. 要严谨（rigor → quality）

- **模糊输入**：「认真点别敷衍」
- **候选**：① 严谨与质量（防敷衍 / 自检 / 评审）② 通用与入门
- **深挖**：对什么把关？最担心敷衍 / 漏检 / 不一致中的哪类？
- **串联**：元谨 yotta-anti-shallow（代码场景：元质 yotta-code-quality）
- **可跑提示词**：
  > 请认真、严谨地完成 <任务>：先分析、再执行、后自检，逐条核对是否有敷衍 / 漏检 / 不一致。（若已安装元谨 yotta-anti-shallow，请按它的规则引擎自检；涉及代码另按元质 yotta-code-quality 结对评审）

## 9. 不知道问什么（no-idea → general）

- **模糊输入**：「我不知道怎么问」
- **候选**：① 通用与入门（先理清再说）② 让用户从常见方向挑
- **深挖**：你现在手上最想解决的一件事是什么？它是写东西、查东西、记东西，还是别的？
- **串联**：元引自身（先澄清，再分流到具体技能）
- **可跑提示词**：
  > 我现在还不太清楚想要什么，请先问我 2-3 个问题帮我理清目标（要什么结果 / 与什么相关 / 输出形态），再给出可执行方案；如果合适，推荐一个元阁技能。

## 10. 写周报 / 总结（weekly-report → writing）

- **模糊输入**：「帮我把这周的工作写成周报」
- **候选**：① 写作与语言（周报 / 总结 / 润色）② 数据与整理（把工作量化成数据）
- **深挖**：本周做了哪几件事？有什么数据 / 成果？给谁看？要多详细？
- **串联**：元真 yotta-humanize（可选加速；未安装不影响）
- **可跑提示词**：
  > 请以中文帮我把这周的工作写成周报：工作事项 <事项>，成果 / 数据 <成果>，下周计划 <计划>，语气 <简洁 / 正式>。先列要点再成文，避免套话与过度正式。（若已安装元真 yotta-humanize，请先跑检测评分再改写）

## 11. 做表格整理数据（data-table → analysis）

- **模糊输入**：「帮我整理数据做个表格」
- **候选**：① 数据与整理（表格 / 统计 / 汇总）② 写作与语言（写说明）
- **深挖**：数据从哪来？要什么字段 / 维度？输出表格还是统计结论？
- **串联**：无专属技能（提示词自包含）
- **可跑提示词**：
  > 请帮我处理这份数据 / 材料 <来源>：目标 <要得到什么>，输出 <表格 / 统计 / 汇总 / 结论>。先说明处理思路，再给出结构化结果；涉及敏感信息请先脱敏。

## 12. 制定学习计划（learn-plan → planning）

- **模糊输入**：「帮我定个学习计划」
- **候选**：① 计划与组织（拆解 / 排期）② 学习与教学（学什么）
- **深挖**：学什么主题？目标是什么（考试 / 入门 / 进阶）？每天能投入多少时间？
- **串联**：无专属技能（提示词自包含）
- **可跑提示词**：
  > 请帮我制定 <计划主题>：目标 <目标>，期限 <时间>，约束 <限制>。拆解成可执行步骤与里程碑，标出依赖与风险，并给一个待办清单。

## 13. 写演讲稿 / 述职（speech → writing）

- **模糊输入**：「帮我写个述职演讲稿」
- **候选**：① 写作与语言（演讲稿 / 述职）② 计划与组织（梳理内容框架）
- **深挖**：讲给谁听？时长多少？要突出哪些成果？风格（稳重 / 有感染力）？
- **串联**：元真 yotta-humanize（可选加速）
- **可跑提示词**：
  > 请以中文帮我写一份 <时长> 的演讲稿 / 述职稿：听众 <对象>，核心要点 <要点>，风格 <风格>。先给结构（开场 / 主体 / 收尾），再成文，避免空话套话。（若已安装元真 yotta-humanize，请先跑检测评分再改写）

## 14. 翻译文档（translate → writing）

- **模糊输入**：「帮我翻译这段英文」
- **候选**：① 写作与语言（翻译 / 润色）② 学习与教学（顺便学词句）
- **深挖**：什么语言对？什么领域（商务 / 技术 / 文学）？要直译还是意译？
- **串联**：元真 yotta-humanize（可选加速）
- **可跑提示词**：
  > 请把这段 <源语言> 翻译成 <目标语言>：领域 <领域>，风格 <直译 / 意译>，长度 <限制>。先给译文，再标注关键术语的译法选择。（若已安装元真 yotta-humanize，请检查译文是否有翻译腔并改写）

## 15. 整理会议纪要（meeting-notes → writing）

- **模糊输入**：「把会议内容整理成纪要」
- **候选**：① 写作与语言（纪要 / 总结）② 数据与整理（列事项清单）
- **深挖**：会议讨论了什么？有哪些决定 / 待办 / 负责人？给谁看？
- **串联**：元真 yotta-humanize（可选加速）
- **可跑提示词**：
  > 请把这段会议内容整理成纪要：结构 = 议题 / 决定 / 待办（含负责人与截止时间）。保持简洁客观，不添加未讨论的内容。（若已安装元真 yotta-humanize，请检查是否有冗余表达并精简）

## 16. 审阅合同 / 文书（contract → quality）

- **模糊输入**：「帮我审一下这份合同」
- **候选**：① 严谨与质量（条款核对 / 风险点）② 写作与语言（措辞润色）
- **深挖**：审阅目的是什么（风险 / 一致性 / 合规）？最担心哪类条款？
- **串联**：无专属技能（提示词自包含）
- **可跑提示词**：
  > 请认真审阅这份合同 / 文书：关注 <关注点：条款风险 / 前后一致性 / 措辞歧义>。逐条列出问题、影响与修改建议，标注优先级；不确定的法律结论请明确说明需人工复核。

## 17. 头脑风暴 / 策划（brainstorm → planning）

- **模糊输入**：「帮我想几个活动创意」
- **候选**：① 计划与组织（策划 / 拆解）② 写作与语言（文案）
- **深挖**：给什么活动 / 产品想创意？目标人群是谁？约束（预算 / 时间 / 渠道）？
- **串联**：无专属技能（提示词自包含）
- **可跑提示词**：
  > 请帮我为 <主题> 头脑风暴：目标人群 <人群>，约束 <预算 / 时间 / 渠道>。先给 5-8 个方向各一句话，再挑 2-3 个展开成可执行方案；不要只给一个答案。

## 18. 准备面试（interview → learning）

- **模糊输入**：「帮我准备后端面试」
- **候选**：① 学习与教学（知识梳理 / 练习）② 计划与组织（复习计划）
- **深挖**：什么岗位 / 级别？面试哪几轮（八股 / 项目 / 系统设计）？什么时候面？
- **串联**：无专属技能（提示词自包含）
- **可跑提示词**：
  > 请帮我准备 <岗位> 面试：常见问题 <范围>，我的项目经历 <项目>。先列出高频问题与回答框架，再模拟追问 2-3 轮并给我的回答打分、给改进建议；把不会的点整理成复习清单。
